माझी मातृभाषा फ्रेंच आहे, पण माझं बहुतांश सॉफ्टवेअर काम — कमिट मेसेज, कोड कमेंट्स, GitHub issues, आंतरराष्ट्रीय टीम्सशी चॅट, डॉक्युमेंटेशन — इंग्रजीत चालतं. अस्खलित इंग्रजी टाइप करणं अवघड नाही; खरी अडचण म्हणजे मेंदूचा बाकीचा भाग मातृभाषेत काम करत असताना इंग्रजीत *विचार* करणं. स्वतः भाषांतर करावं लागलं नाही, तर डिक्टेशन ही अडचण पूर्णपणे दूर करतं.

## सेटअप

मी opons-voxd दोन स्वतंत्र push-to-talk हॉटकीजसह चालवतो:

- **`Ctrl+Alt+W` — सामान्य डिक्टेशन.** दाबून ठेवतो, फ्रेंचमध्ये बोलतो, सोडतो, कर्सरवर फ्रेंच मजकूर टाइप होतो. नोट्ससाठी, फ्रेंच सहकाऱ्यांशी चॅटसाठी, आणि जे काही फ्रेंचमध्येच राहायला हवं त्यासाठी.
- **`Ctrl+Alt+K` — डिक्टेशन-आणि-भाषांतर.** तीच कृती, पण मी फ्रेंच बोलतो आणि कर्सरवर *इंग्रजी* येतं. इंग्रजी वाचकांसाठी असलेल्या प्रत्येक गोष्टीसाठी: कमिट मेसेज, PR वर्णनं, कोड कमेंट्स, GitHub issues, इंग्रजी चॅट चॅनेल्स.

भाषांतरकात कॉपी-पेस्ट नाही, संदर्भ बदलणं नाही, पुन्हा टाइप करणं नाही. मी बोलतो, आणि माझा कर्सर जिथे आधीच आहे तिथेच इंग्रजी दिसतं.

## दोन हॉटकीज का, एक का नाही

भाषांतर तेव्हाच नीट काम करतं जेव्हा मॉडेल खरोखर त्याच कामासाठी प्रशिक्षित असतं. रोजच्या फ्रेंच हॉटकीसाठी मी `large-v3-turbo` वापरतो कारण तो वेगवान आहे — पण त्याची भाषांतर गुणवत्ता खराब आहे, कारण तो ट्रान्सक्रिप्शनच्या वेगासाठी ऑप्टिमाइझ केलेला आहे, भाषांतरासाठी नाही. भाषांतर हॉटकी त्याऐवजी दुसरं मॉडेल (`medium`) लोड करते जे योग्यरित्या भाषांतर करतं. दोन्ही मॉडेल्स एकाच वेळी GPU मेमरीत राहतात; काही GB पेक्षा जास्त जागा असलेल्या कार्डवर हा अतिरिक्त खर्च नगण्य असतो.

## करून बघा

ही opons-voxd ची प्रमाणित रचना आहे — कोणत्याही fork किंवा patch ची गरज नाही. `OPONS_VOXD_PTT_HOTKEY`, `OPONS_VOXD_PTT_TRANSLATE_HOTKEY`, `OPONS_VOXD_TRANSLATE_MODEL` आणि `OPONS_VOXD_LANGUAGE` साठी मुख्य README मधील [Configuration](../README.md#configuration) आणि [Push-to-talk-and-translate hotkey](../README.md#push-to-talk-and-translate-hotkey) पाहा.

तुम्ही रोज इंग्रजीव्यतिरिक्त दुसरी भाषा बोलत असाल, पण काम इंग्रजीत करत असाल, तर हे कदाचित या प्रोजेक्टमधलं सगळ्यात उपयुक्त फीचर आहे.
